### GMAIL_FETCH_EMAILS

**MCP Tool**: `mcp__composio__GMAIL_FETCH_EMAILS`

Fetches a list of email messages from a Gmail account, supporting filtering, pagination, and optional full content retrieval.

**Parameters:**
  - `ids_only` (boolean, optional): If true, only returns message IDs from the list API without fetching individual message details. Fastest option for getting just message IDs and thread IDs.
  - `include_payload` (boolean, optional): Set to true to include full message payload (headers, body, attachments); false for metadata only.
  - `include_spam_trash` (boolean, optional): Set to true to include messages from 'SPAM' and 'TRASH'.
  - `label_ids` (array, optional): Filter by label IDs; only messages with all specified labels are returned. System label IDs (can be used directly): 'INBOX', 'SPAM', 'TRASH', 'UNREAD', 'STARRED', 'IMPORTANT', 'CATEGORY_PRIMARY' (alias 'CATEGORY_PERSONAL'), 'CATEGORY_SOCIAL', 'CATEGORY_PROMOTIONS', 'CATEGORY_UPDATES', 'CATEGORY_FORUMS'. IMPORTANT: For custom/user-created labels, you MUST use the label ID (e.g., 'Label_123456'), NOT the label name shown in Gmail UI. For example, if you have a label named 'BlocksToDo' in Gmail, you cannot pass 'BlocksToDo' - you must first call the 'listLabels' action to find the corresponding ID (something like 'Label_7890') and use that ID here. Passing a label name instead of ID for custom labels will result in an 'Invalid label' error.
  - `max_results` (integer, optional): Maximum number of messages to retrieve per page.
  - `page_token` (string, optional): Token for retrieving a specific page, obtained from a previous response's `nextPageToken`. Must be a valid opaque token string from a previous API response. Do not pass arbitrary values. Omit for the first page.
  - `query` (string, optional): Gmail advanced search query (e.g., 'from:user subject:meeting'). Supports operators like 'from:', 'to:', 'subject:', 'label:', 'has:attachment', 'is:unread', 'after:YYYY/MM/DD', 'before:YYYY/MM/DD', AND/OR/NOT. Use quotes for exact phrases. Omit for no query filter.
  - `user_id` (string, optional): User's email address or 'me' for the authenticated user.
  - `verbose` (boolean, optional): If false, uses optimized concurrent metadata fetching for faster performance (~75% improvement). If true, uses standard detailed message fetching. When false, only essential fields (subject, sender, recipient, time, labels) are guaranteed.
